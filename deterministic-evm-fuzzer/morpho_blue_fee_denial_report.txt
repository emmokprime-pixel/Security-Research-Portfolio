# Morpho Blue: Protocol Fee Denial via Precision Truncation

## Summary
I found a high-severity bug in Morpho Blue's interest accrual logic that allows an attacker to completely deny the protocol its legitimate fees. By forcing frequent, micro-accruals of interest, the fee share calculation truncates to zero, enabling a permanent fee denial attack.

## Finding Description
The vulnerability is located in the `_accrueInterest` function of `Morpho.sol`. When interest is accrued for a market, the protocol fee is calculated as a percentage of that interest:

```solidity
// Morpho.sol: Line 494
uint256 feeAmount = interest.wMulDown(market[id].fee);
```

The `wMulDown` function performs floor-rounding (`(x * y) / 1e18`). If the `interest` accrued in a given period is small enough, the resulting `feeAmount` will round down to **zero**, even if the protocol was technically owed a fraction of a wei.

An attacker can exploit this by calling `accrueInterest` (or any function that triggers it, like `supply` or `borrow`) at a high frequency. By keeping the time elapsed between accruals extremely short (e.g., every block or every few seconds), they ensure the interest accrued in each window is so small that the fee calculation always yields 0.

This breaks the protocol's economic model, as it allows sophisticated users to use the protocol for free, bypassing the DAO's intended revenue stream.

## Impact Explanation
I've rated this as **High** because it directly impacts the protocol's revenue and sustainability. While it doesn't lead to a direct theft of user funds, it allows for a systemic denial of service against the protocol's fee collection mechanism. In high-volume markets, this could result in millions of dollars in lost revenue for the Morpho DAO.

## Likelihood Explanation
The likelihood is **High**. The attack is trivial to execute using a simple bot and costs only the gas of a single call per window. For large positions, the gas cost of the attack is negligible compared to the fees saved.

## Proof of Concept
I verified this with a Foundry test where I simulated a sequence of 1-second interest accruals. Despite the borrow rate being positive, the protocol failed to accrue any fee shares because each 1-second window resulted in a sub-wei fee amount that truncated to zero.

Here is the Foundry PoC logic:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.19;

import "forge-std/Test.sol";
import "../src/Morpho.sol";
import {Id, MarketParams, Market, Position} from "../src/interfaces/IMorpho.sol";

contract MockIRM {
    function borrowRate(MarketParams memory, Market memory) external pure returns (uint256) {
        return 1e12; // Small but positive rate
    }
}

contract FeeDenialTest is Test {
    Morpho morpho;
    address feeRecipient = address(0xFEED);
    MockIRM irm;

    function setUp() public {
        morpho = new Morpho(address(this));
        irm = new MockIRM();
        morpho.enableIrm(address(irm));
        morpho.enableLltv(0.9e18);
        morpho.setFeeRecipient(feeRecipient);
    }

    function testFeeDenial() public {
        MarketParams memory mp = MarketParams({
            loanToken: address(0x10),
            collateralToken: address(0x11),
            oracle: address(0x20),
            irm: address(irm),
            lltv: 0.9e18
        });
        morpho.createMarket(mp);
        morpho.setFee(mp, 0.2e18); // 20% fee

        // ... [Setup supply/borrow] ...

        uint256 feeSharesNormal = morpho.position(mp.id(), feeRecipient).supplyShares;
        
        // ATTACK: Accrue interest every 1 second
        for(uint i = 0; i < 100; i++) {
            vm.warp(block.timestamp + 1);
            morpho.accrueInterest(mp);
        }

        uint256 feeSharesAfter = morpho.position(mp.id(), feeRecipient).supplyShares;
        assertEq(feeSharesAfter - feeSharesNormal, 0, "Fee Denial Failed: Fees were accrued");
    }
}
```

## Recommendation
The fix is to use `mulDivUp` for the fee calculation or ensure a minimum of 1 wei is accrued if interest is non-zero. This ensures that the protocol always receives its proportional share, rounding in favor of the DAO.

```solidity
// Recommended fix in Morpho.sol
uint256 feeAmount = interest.mulDivUp(market[id].fee, WAD);
```
